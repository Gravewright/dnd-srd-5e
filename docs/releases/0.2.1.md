# DnD 5e SRD 0.2.1 Alpha

## Faster initiative and fewer repeated updates

- On VTT 0.3.8, new initiative operations use the public native batch capability. DnD formulas and revisions are prepared in the package; the host commits rolls, initiative order and grouped chat results together, preserving permissions and hidden results.
- Retrying a lost response reuses the durable plan and UUID. Revision conflicts require fresh source reads. Older journals and VTT 0.2.3/0.3.7 retain sequential recovery; a pending native batch requires a capable host to resume after a downgrade.
- Reduce sequential API/storage calls, bound sheet reads and pace legacy rolls against the chat quota. Tracker updates are coalesced, and unchanged displays preserve controls and menus.
- Share actor subscriptions across open sheets, skip unrelated updates and protect edits and permissions from delayed reads. Independent token sheets retain their own data.

With twenty participants, Chromium and local SQLite, three real `1d20 + @init`
runs took 883–948 ms from the actual click until GM and player displayed the
order and twenty chat results (median 925 ms). These local samples do not promise
the same latency over a network. Turn advancement showed no material improvement.
See [method, measurements and limits](../performance.md).

## Installation

Download `gravewright-5e-srd-0.2.1.zip` and verify its SHA-256 sidecar. Install
through the VTT local system installer, select 0.2.1 in the table extensions and
reload open tables. Use VTT 0.3.8 for native initiative batches; 0.2.3 and 0.3.7
remain supported through the sequential path. Keep previous system versions for
rollback. No separate Server Rules module is required. Existing sheets, content
and the stable system ID `gravewright.5e-srd` are preserved. Marketplace
availability depends on its catalog.

## Português brasileiro

- No VTT 0.3.8, novas iniciativas usam o lote nativo público. O pacote prepara fórmulas DnD e revisões; o host confirma dados, ordem e resultados agrupados no chat juntos, preservando permissões e resultados ocultos.
- Repetir uma resposta perdida reutiliza o plano persistido e o UUID. Conflitos exigem novas leituras. Registros antigos e hosts 0.2.3/0.3.7 mantêm recuperação sequencial; um lote nativo pendente exige um host compatível para retomar após downgrade.
- O caminho sequencial reduz chamadas, limita leituras de fichas e espaça rolagens conforme o limite do chat. O tracker agrupa atualizações e preserva controles e menus quando a apresentação não muda.
- Fichas compartilham assinaturas de atores, ignoram atualizações irrelevantes e protegem edições e permissões contra respostas atrasadas. Tokens independentes mantêm seus próprios dados.

Com vinte participantes, Chromium e SQLite local, três execuções reais de
`1d20 + @init` levaram 883–948 ms do clique até mestre e jogador exibirem ordem
e vinte resultados no chat (mediana 925 ms). São amostras locais, sem promessa
de igual latência pela rede. O avanço de turno não teve ganho relevante. Veja
[método, medições e limites](../performance.pt-BR.md).

Baixe `gravewright-5e-srd-0.2.1.zip`, confira o SHA-256, instale pelo instalador
local de sistemas, selecione 0.2.1 nas extensões da mesa e recarregue as páginas.
Use o VTT 0.3.8 para iniciativa em lote; 0.2.3 e 0.3.7 continuam compatíveis pelo
fluxo sequencial. Preserve versões anteriores para reversão. Não é necessário

preservados. A disponibilidade no Marketplace depende do catálogo.
